## 1. 目标与结论

当前远程下载在提交磁力链接后直接创建全量下载任务。目标是让用户先看到链接包含的文件，再决定下载哪些文件，避免广告、说明文件、不需要的剧集等被一并下载。

**可以支持，推荐复用迅雷云端资源解析与文件索引协议。** 迅雷官方远程页面已经实现该流程。本项目已经具备登录、令牌续期、资源解析和任务创建能力，主要工作是独立提供解析接口、增加文件选择界面，并将所选文件纳入创建参数和提交记录。

首版应做到：

1. 解析链接只获取资源信息，不创建下载任务。
2. 磁力资源展示文件树、文件大小、所选数量和总大小。
3. 用户确认后，仅将明确选择的文件索引下发给迅雷。
4. 解析失败、列表不完整、没有选择、预览过期时，均不自动退回全部下载。
5. 重试、刷新页面、服务重启及切换账号或设备，不得导致重复提交或下载另一组文件。

预计属于中等规模的前后端改动，不需要修改挂载、隔离环境或嵌入认证程序。

必须保留的现有约束：

- 下载目录通过设备目录服务真实解析，保留有效空格，不能因选文件而改用默认目录或自行拼接宿主机路径。
- 创建任务前先原子保存提交记录；写入或同步失败时不继续发送创建请求。
- 创建任务、短信、任务操作不能采用通用网络自动重试。
- 当前提交核对窗口固定为原提交前 5 秒至后 60 秒，最多检查五页，正常到达末页且候选唯一才可确认。
- 状态文件保存权限为 `0600`，预览信息不得混入账号令牌响应。
- 写接口沿用 JSON、`X-XLP-Request: 1`、跨站请求保护；静态资源继续遵守现有内容安全策略。
- 远程客户端是一份共享账号状态，不应为此次功能另建多用户权限体系。

| 阶段 | 接口 | 官方代码读取或提交的字段 |
| --- | --- | --- |

官方对已加载叶子直接使用 `file_index`；对勾选但尚未展开的目录，调用 `resource/indices` 取得真正的叶子索引。它不会把目录节点编号直接交给 `sub_file_index`。

### 3.3 选择参数

先去重，再按数值排序，将连续索引压缩为闭区间，逗号分隔，不添加尾逗号：

| 所选索引 | 参数值 |
| --- | --- |
| `[0]` | `"0"` |
| `[0, 2, 3, 5]` | `"0,2-3,5"` |
| `[5, 3, 2, 2, 0]` | `"0,2-3,5"` |
| `[]` | 拒绝创建文件选择任务 |

`file_index` 是真实协议索引，不是页面行号，也不能根据文件名排序后重新编号。索引零有效，不能用真假判断丢弃。

官方创建参数中，顶层 `file_size` 是所选文件大小之和；`params.total_file_count` 仍是原资源文件总数。一个磁力仍创建一个下载任务，内部包含所选子文件。

## 4. 首版范围与交互决策

建议首版采用“有界完整解析”：在设定上限内补齐全部目录和文件，完整成功后才允许选择及创建。先不做后台解析任务系统，也不引入 DHT 或新的下载引擎。

用户流程：

```text
输入链接与选择保存目录
  ↓ 点击“解析链接”
逐条解析，显示每条的成功、失败或超限状态
  ↓
勾选文件，查看已选数量和总大小
  ↓ 点击“下载所选文件”
逐条创建，显示成功、明确失败或结果未知
```

具体规则：

1. 保留最多 50 条链接的输入方式，每条独立展示结果，允许跳过某条。
2. 多文件资源默认不勾选，提供全选、取消全选、目录勾选和仅选视频；仅选视频不会自动包含字幕，应让用户继续手动选择。
3. 目录复选框支持全选、部分选中和未选中三态。仅叶子文件进入最终选择集合，空目录不作为下载项。
4. 对完整解析出的单文件直链，可默认选择唯一文件；磁力即使只有一个文件，也进入可见的确认流程。
5. `thunder://` 先解码，内部是磁力时遵守磁力规则。其他链接若实际解析出多文件资源，也必须先选文件，不能只靠 URL 后缀判定。
6. 解析成功不等于用户同意下载；没有点击最终按钮，不得调用任务创建接口。
7. 按名称或大小排序只影响展示。搜索和复杂过滤可延后，首版避免“全选”究竟作用于全部还是搜索结果的歧义。
8. 批量里有失败项时，明确显示“将提交几条、跳过几条”，只提交完整成功且存在选择的项，不自动重试失败项。
9. 解析可以取消。任务已发出后，不能把关闭窗口或浏览器中止请求解释为任务取消。
10. 解析过期后重新解析，只有资源内容版本一致时才可以恢复原选择；内容变化时清空选择并说明原因。

## 5. 本地数据模型

建议在 `pkg/remote/resource.go` 中放置解析和索引处理，不继续把所有逻辑堆到 `drive.go`。

### 5.1 对页面返回的资源预览

```json
{
  "preview_id": "7d08a560ef55488c9e2d11fe2b472f36",
  "resource_version": "服务端计算的六十四位十六进制摘要",
  "url": "magnet:?xt=urn:btih:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "target": "示例设备",
  "kind": "files",
  "name": "示例资料包",
  "total_file_count": 2,
  "total_size": "300",
  "complete": true,
  "expires_at": "2026-11-15T12:10:00Z",
  "files": [
    {
      "id": "示例根目录",
      "parent_id": "",
      "name": "示例资料包",
      "is_dir": true,
      "size": "300"
    },
    {
      "id": "示例文件甲",
      "parent_id": "示例根目录",
      "name": "视频.mp4",
      "is_dir": false,
      "index": 0,
      "size": "100"
    },
    {
      "id": "示例文件乙",
      "parent_id": "示例根目录",
      "name": "说明.txt",
      "is_dir": false,
      "index": 1,
      "size": "200"
    }
  ]
}
```

这是本地接口示例，不是实际抓包。字段约定：

- `kind` 使用 `files` 表示可按索引选择的资源，`single` 表示确认只有一个下载对象的普通直链。
- 文件树可用扁平数组加 `parent_id` 表示，便于校验、缓存和页面重建；避免直接向页面转发上游任意对象。
- `index` 仅对有真实索引的叶子返回；Go 使用指针或显式存在标志，不能用 `omitempty` 丢弃整数零。
- 所有大小使用十进制字符串传给页面；Go 内部使用 `int64`，页面汇总使用 `BigInt`，只在格式化近似显示时转换，避免大整数精度丢失。
- 文件索引使用非负整数。对网页协议明确限制在 JavaScript 安全整数范围内，不能把超大索引转换成失真的数字；不要用文件数量上限代替索引值上限。
- `id` 只用来关联展示节点，索引才是下载选择身份。不同目录的同名文件必须能分别勾选。
- `resource_version` 为服务端对规范化资源内容计算的 SHA-256；建议包含按真实索引排序的叶子索引、原始路径段和大小，以及资源模式和总数。单文件直链没有索引时，编码模式、单个对象的名称和大小，不补造索引。用确定性的结构化编码，不用换行拼接任意文件名。
- 内容版本不包含临时 `list_id`、临时节点编号、过期时间或上游返回顺序；同一内容重新解析应得到相同版本。
- 首版只返回 `complete: true` 的可用预览。不完整解析返回错误，不发放能创建任务的 `preview_id`。
- 页面展示文件名使用 `textContent`，不将资源名称作为 HTML、脚本或本地路径执行。

### 5.2 服务端内部快照

内部快照额外保存当前账号标识、会话代数、完整规范化链接、设备、有效期、根资源摘要和 `index → 叶子元数据` 映射。页面提交时，服务端用该映射核对选择并计算大小。

上游 `list_id` 只供分页查询；本地 `preview_id` 用随机 128 位标识，不直接复用上游编号。解析完整后，下发文件选择任务无需再次依赖云端列表仍然存在。

## 6. 本地接口建议

### 6.1 解析

新增 `POST /api/remote/resources/resolve`：

```json
{
  "target": "示例设备",
  "url": "magnet:?xt=urn:btih:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
}
```

一次处理一条规范化链接，不在一个请求内顺序解析 50 条。当前页面可以维护队列，首版每次只发一个解析请求，使其他客户端操作有机会获得锁。

处理顺序：取得操作锁，校验设备，复用现有认证，规范化链接，调用资源接口，补齐分页，校验文件树，生成内容版本，发布完整快照，返回上一节的数据。

解析不需要先访问保存目录，不应因用户尚未选目录而阻止查看磁力内容。可以复用同账号、设备、链接下仍有效的完整快照；不要复用失败结果或半成品。

### 6.2 创建下载

扩展现有 `POST /api/remote/tasks`：

```json
{
  "request_id": "2e1df65a35a4479f80abf606ab22eb38b",
  "target": "示例设备",
  "directory": "/downloads/视频",
  "url": "magnet:?xt=urn:btih:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "preview_id": "7d08a560ef55488c9e2d11fe2b472f36",
  "resource_version": "服务端此前返回的内容摘要",
  "selection_mode": "files",
  "file_indices": [0]
}
```

上述请求选择两文件预览中的视频文件。`selection_mode: "files"` 必须有非空合法集合，`single` 不接受子文件集合。两种模式的新页面请求都携带预览及内容版本。

服务端不接受页面提供的文件名、总大小、文件总数或编码后的 `sub_file_index` 作为权威参数。索引去重排序后，必须全部存在于当前快照。

成功响应继续复用 `{ "id": "任务编号", "reused": false }`。已有请求成功时返回同一任务编号并将 `reused` 置为 `true`。

### 6.3 只检查已提交结果

建议新增 `GET /api/remote/submissions/{request_id}?target=示例设备`，服务方法可命名为 `CheckSubmission`。

它只读取本地提交记录及必要的云端任务列表，绝不调用任务创建接口。确认到任务后允许保存本地确认结果。响应可以采用：

```json
{
  "request_id": "2e1df65a35a4479f80abf606ab22eb38b",
  "status": "confirmed",
  "task_id": "任务编号"
}
```

`status` 定义为 `confirmed`、`unknown`、`missing`。已有未确认记录返回 `unknown`；找不到记录返回 `missing`，并不意味着从未发送过任务。

新增该接口的目的，是让结果未知项在预览过期、服务重启或浏览器恢复旧记录后仍可只核对结果，也避免服务端七天后清理记录时，页面再次调用创建接口意外生成新任务。

需要校验当前设备和记录设备相符。不同账号的记录不得查询；当前账号切换和退出仍遵守项目已有状态清理行为，不承诺跨账号恢复。

## 7. 资源解析和分页算法

### 7.1 补齐树的流程

1. 对单条链接请求 `resource/list`，取得根资源、`list_id` 和初始节点。
2. 检查顶层业务结果和各节点的资源级错误；不能仅因为 `resources` 非空就判定成功。
3. 遍历节点，将每个带 `dir.next_page_token` 的目录加入工作队列，保存该令牌所属的目录。
4. 请求 `resource/list/{list_id}`，将返回的 `list.resources` 合并到对应目录；更新该目录的后续令牌，并收集新发现的子目录分页。
5. 如果实际响应还有顶层 `list.next_page_token`，也按根列表补齐；该形态需要结合真实响应验证，不能把顶层页面与目录页面混合。
6. 所有分页都读完后，校验父子关联、索引、大小、资源总数及结构完整性，生成不可变快照。

实现注意：

- 分页令牌按不透明字符串处理，使用 `url.Values` 编码；`list_id` 作为受限路径段处理，不能拼成任意上游 URL。
- 对每个分页链记录已访问令牌，检测自循环和多步循环；同时设置全局请求数上限，避免大量不同令牌绕过限制。
- 相同节点编号的完全相同数据可去重；同编号不同内容、同一叶子索引对应不同文件、父子环或无法解释的多根结果应拒绝。
- 文件与目录同名不构成重复，不能按文件名去重。
- 不将缺失 `file_index` 当作零，不从页面顺序补造索引，不把 `file_id` 当作 `file_index`。
- 对普通单文件直链没有文件索引的情况使用 `single` 模式。磁力缺少可验证叶子索引时提示不支持选择，不能静默全部下载。
- 计数比较应建立在字段语义已确认的前提下。原资源总数明确且与完整叶子数量不一致时不能声称完整；上游存在填充文件等例外时先以真实样本确认。
- 名称中的斜线、路径段和目录层级应保留可区分语义，不用操作系统 `filepath.Clean` 重写资源身份。

### 7.2 首版资源上限

以下是建议初值，应集中为常量并编写边界测试。它们不是迅雷官方限制，可以根据实际响应和内存测量调整。

| 项目 | 建议初值 | 超限处理 |
| --- | --- | --- |
| 单条预览叶子文件 | 5000 | 返回资源过大，不允许创建 |
| 单条预览全部节点 | 10000 | 同上，包含目录 |
| 最大目录深度 | 64 | 返回结构异常或资源过大 |
| 单条解析上游请求总数 | 64，包含首次请求 | 停止解析，不返回完整预览 |
| 单次解析总时长 | 60 秒，包含等待操作锁 | 取消请求并提示重试；不延长现有 90 秒网页超时 |
| 单个规范化预览序列化大小 | 4 MiB | 不写入缓存，不返回部分成功 |
| 缓存条目数 | 64 | 清理过期项后仍满则拒绝新增 |
| 缓存累计规范化数据大小 | 64 MiB | 同上；另测实际 Go 堆开销 |
| 创建接口请求正文 | 128 KiB | 仅按需提高创建接口上限，其他接口保持 32 KiB |

还应给单条解析设置累计响应字节预算，例如 16 MiB，并保留现有每个上游响应 8 MiB 限制。按规范化数据大小计费不能替代实际内存分析，原始响应树处理完应及时释放，不同时永久保留两份大对象。

提高创建正文上限，是因为长链接加数千个文件索引可能超过当前 32 KiB；仍应先限制数组元素数量，不能只扩大正文限制。

### 7.3 后续扩展

超大种子可在下一阶段采用按目录加载，并利用 `resource/indices` 转换选中目录。该方案需要明确未加载文件的全选语义、所选大小统计、排除项及索引接口的数组编码，复杂度高于首版。

不要为了避开分页直接把 `page_size` 改成极大值，也不要把第一页的“全选”表达成整个磁力的全选。

## 8. 预览缓存、会话和并发

预览只保存在客户端内存，不写入现有账号状态文件。建议有效期十分钟，从完整解析完成时计算；上游列表的实际有效期仍需验证，两者不是同一个期限。

建议缓存键包含账号标识、会话代数、设备和本地预览编号。手动登录、退出、账号变化、设备切换或客户端关闭时清除相关预览；普通令牌续期不应无故使所有预览失效。修改保存目录不必清除预览，但创建时必须重新校验实际目录。

缓存和分页使用现有 `gate` 保护，避免新增容易与状态锁形成死锁的锁顺序。对外的 `ResolveResource` 取得一次操作锁，内部调用不再重复取得锁。`Status()` 继续只读状态，不等待解析网络。

容量满时优先清理过期项，不静默淘汰用户正在选择的有效预览。前端可以释放本窗口未提交的预览作为后续优化，首版不必为此新增后台任务。

浏览器取消请求后检查上下文，停止继续分页，不发布半成品。若完整结果已经发布但响应丢失，该缓存只会过期，不会触发下载。

切换账号或设备时，缓存应跟随“实际采用的状态”失效，不能只看配置方法是否返回成功。现有原子保存逻辑可能在文件已替换、目录同步失败后返回错误，此时内存已经采用新状态。

## 9. 创建流程与上游参数

建议按以下顺序实现，避免预览过期阻断已有请求的查询：

1. 取得操作锁，校验请求编号、当前设备、链接、目录和选择字段的基本格式。
2. 查找已有提交记录。若存在，使用记录版本进行指纹校验；已知任务直接返回，未知任务只核对，不重新创建。这个分支不要求有效预览。
3. 携带新版字段的首次创建，无论 `files` 还是 `single`，都必须存在有效预览，且账号、设备、规范化链接、内容版本、模式均匹配。只有全部新版字段均未提供的旧格式请求，才进入后文约定的单文件兼容分支。
4. 规范化选择集合，核对全部索引属于该资源，计算所选大小并检查溢出。
5. 使用现有目录服务解析真实父目录编号与路径。
6. 在所有网络准备完成后、落盘前再次检查取消及预览有效期；构造不可变的创建意图。
7. 先原子保存带选择信息的提交记录，保存失败则停止。
8. 调用一次任务创建接口。仅保留现有“业务明确拒绝后续期认证”的受控处理，不对网络中断或超时重发。
9. 成功取得任务编号后保存结果；远端结果不明时保留记录并返回未知状态。

示意上游正文：

```json
{
  "type": "user#download-url",
  "name": "示例资料包",
  "file_name": "示例资料包",
  "file_size": "100",
  "space": "示例设备",
  "params": {
    "target": "示例设备",
    "url": "magnet:?xt=urn:btih:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "total_file_count": "2",
    "parent_folder_id": "服务端解析的目录编号",
    "parent_folder_path": "/downloads/视频/",
    "sub_file_index": "0"
  }
}
```

沿用本项目已有可用字段；`mime_type`、`file_id` 等是否需要继续发送，以现有兼容性及实际联调为准。不要不加判断地照搬官方前端所有参数，也不要删掉本项目已经用于正确下发设备目录的参数。

即使全选，也建议发送完整显式索引或压缩区间，不恢复使用 `"--1,"`。对明确单文件直链保留原可用语义，但不能将该兼容路径用于多文件磁力。

大小按已选叶子累计，每个索引只计一次，不把目录大小和其子文件大小重复相加。任务列表最终展示若由上游重新计算总大小，应记录实际行为后适配，不将前端预览数字伪装成设备实时进度。

## 10. 提交记录、去重和历史兼容

### 10.1 新记录

建议保留原有字段，增加 `version: 2`、账号标识、`selection_mode`、`resource_version`、规范化选择字符串及所选大小。选择可用 `"0,2-3,5"` 存储，避免给已有状态浅复制逻辑引入可变切片共享。

新版指纹采用确定性结构化编码后计算摘要，至少覆盖：

```text
版本、账号、设备、规范化目录、规范化链接、资源内容版本、选择模式、规范化索引集合
```

不要将 `preview_id` 纳入指纹：同一资源重新解析后编号可变，但实际创建意图不变。不要用不转义的换行连接任意目录或文件名。

页面的逻辑提交键也必须区分资源内容版本和规范化选择。用户确认创建时才分配 `request_id`，解析和随意勾选阶段不占用提交记录。

同一请求编号变更设备、目录、链接或选择集合必须拒绝。相同集合只是排序不同、重复项不同，可以规范化后视作同一意图。

如果最终选择保存为切片或映射，必须修改 `snapshot`、`updateAndSave` 及测试使用的状态复制逻辑，确保深复制；不能仅 `maps.Clone(Submissions)` 就认为新增嵌套数据已隔离。

### 10.2 旧记录和旧页面

无 `version` 的已有记录按旧版处理，不批量改写指纹，不在升级时清空。未知的新版本记录应明确拒绝处理并保留原数据，不能当成旧记录或未提交状态。

- 旧记录已有任务编号：原编号请求应继续返回原任务，无需资源预览。
- 旧记录结果未知：只能进入核对。对于旧磁力记录，缺少选择证据时保持未知，不以新逻辑重新创建。
- 旧普通单文件任务可以继续使用原有匹配规则；旧磁力若要确认“全量”语义，需有实测可靠的任务证据，不能仅猜测特殊字符串的含义。
- 新请求没有预览：普通直链可按现有流程解析，确认确实只有一个对象后兼容；磁力或实际多文件资源返回 `selection_required`，提示刷新页面并先选择文件。
- 旧浏览器存储只有设备、目录、链接组成的键和 `{id, done}`。新版读取时迁移成历史提交项，不为它生成新的创建编号；未完成项使用只核对接口。

这是对旧磁力创建入口的有意收紧，应同步写入使用说明，避免旧页面继续悄悄全部下载。

### 10.3 未知结果的核对

新版任务模型增加内部选择证据。可首先调查任务 `params.sub_file_index` 是否返回原选择，必要时检查任务详情或设备子文件信息；目前尚未实测保证这些字段存在。

只有原有链接、设备、目录、固定时间窗口条件成立，并且文件集合也能证明确认时，才把新版文件选择提交认定成功。不同任务编号即使集合相同仍属于多个候选，应保留未知。

特别注意：如果窗口内有一条集合匹配的候选，同时还有一条同链接同目录但选择信息缺失的候选，不能直接忽略缺失项后宣布唯一。缺失项仍可能是原提交，整体应保持未知。

来自任务的索引字符串是不可信输入，应限制长度、区间数量、整数范围并规范化。不要展开任意巨大区间到数组；比较可采用受限区间表示，或证明其全部落在当前记录集合后再比较。

未来用户可能在官方客户端修改已创建任务的子文件选择，这时当前选择与原提交不符只能使核对更保守，不能触发再次下载。

### 10.4 记录缺失与重试策略

本项目服务端提交记录目前采用七天阈值惰性清理，最多 2048 条；浏览器记录容量为 100 条。此次不应静默改变这些既有规则。

已标记结果未知的页面项默认使用只核对接口。返回 `missing` 时保留历史提示，让用户在设备中核对，不自动重新发 `POST /tasks`。记录缺失可能是过期清理，也可能是请求从未到达，不能可靠区分。

明确发生在发送前的校验失败，可在纠正后正常重新提交；明确被上游拒绝的请求沿用现有清理记录规则。网络错误、响应丢失、未返回任务编号等都不能被普通“失败重试”按钮自动当作新请求。

## 11. 前端状态和恢复

每条链接建议维护独立状态：

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| `input` | 尚未解析或链接已修改 | 解析、删除输入 |
| `resolving` | 正在解析及补齐分页 | 取消解析 |
| `ready` | 预览完整有效 | 勾选、选择目录、确认下载 |
| `resolve_failed` | 解析失败或超限 | 重新解析、跳过 |
| `submitting` | 已确认并发送创建请求 | 等待结果，不允许修改本次提交意图 |
| `confirmed` | 已取得任务编号 | 查看任务 |
| `rejected` | 明确未创建或明确拒绝 | 按错误修正后重试 |
| `unknown` | 是否创建尚不明确 | 只检查结果，不自动创建 |
| `expired` | 预览失效且尚未提交 | 重新解析 |

界面应保留原输入链接用于展示，但用后端返回的规范化链接构造提交意图。不要仅凭文本前缀判断迅雷专用链接内部类型。

复用现有 `generation`、查询取消和请求有效性检查。为批量解析增加窗口代数和条目代数；关闭重开、编辑某条链接、账号或设备变化时，使旧请求的成功、错误和收尾全部失效。修改一条链接不应清空其他条目的已选状态。

建议区分解析期和提交期的关闭行为：解析期可直接取消；提交期沿用当前创建窗口限制，避免用户误以为关闭就取消下载。浏览器强制离开仍可能发生，因此发送前必须先在内存登记本次请求编号及意图，并尝试写入会话存储；存储不可用时按本节末尾的约定处理。

会话存储建议采用带版本的结构，分别保存未提交草稿和已提交记录。未提交草稿可只保留链接、内容版本及所选索引；页面刷新后重新解析，内容版本一致再恢复选择，不把存储中的 `complete` 或过期时间当作服务端事实。

已提交记录至少保存请求编号、账号展示标识、设备、目录、规范化链接、模式、内容版本、选择集合和结果状态，供恢复后只核对。恢复数据需要校验类型和容量，不能信任存储中的任意字段，也不能为超量旧记录自动分配新编号。

容量满时拒绝新增记录，保留未知记录。关闭窗口可以清理已确认项；未知项不得因关闭窗口、修改输入、批量失败或存储迁移被静默删除。

如浏览器会话存储不可用，继续使用内存状态并说明恢复能力有限；不能声称刷新后一定能保留请求编号。

## 12. 错误类型与重试

沿用 `remote.Error`，新增类型同步到 `remoteweb.writeError` 和页面错误处理。以下为建议映射：

| 类型 | HTTP 状态 | 行为 |
| --- | --- | --- |
| `selection_required` | 400 | 刷新页面并先解析选择；不创建 |
| `invalid_selection` | 400 | 空集合、未知索引、非法模式或整数；不创建 |
| `resource_unavailable` | 422 | 链接有效但未获得可选择的资源；允许用户重新解析 |
| `resource_incomplete` | 422 | 缺失文件索引、总数不符或分页不完整；不创建 |
| `resource_too_large` | 422 | 超过本地预览限制；说明首版范围 |
| `preview_expired` | 409 | 仅影响首次创建；重新解析 |
| `preview_mismatch` | 409 | 预览与账号、设备、链接或版本不一致；不创建 |
| `rate_limited` | 429 | 预览或提交记录容量不足 |
| `submission_unknown` | 409 | 只核对，不能通用重发 |

已存在的登录、设备变化、目录、网络及超时错误继续复用。错误消息使用稳定中文说明，不把上游完整响应、账号令牌、插件凭据或私人磁力链接写入日志。

解析接口虽然使用 POST，但不创建下载任务。首版建议保持手动重试；如果后续增加解析专用有限重试，应明确只作用于资源解析，不能通过修改通用请求函数使全部 POST 自动重发。

## 13. 测试与验收

### 13.1 Go 测试

使用现有替换 `http.Transport` 的方式模拟上游，测试数据放 `t.TempDir()` 或普通内存对象，不依赖已有账号或固定宿主机目录。

| 范围 | 必须覆盖的行为 |
| --- | --- |
| 解析与副作用 | 解析成功、失败、取消都没有请求 `/drive/v1/task`，没有新增提交记录 |
| 文件树 | 单文件磁力、多文件、嵌套目录、空目录、同名文件、Unicode、索引零、稀疏索引 |
| 异常数据 | 缺失索引、非法整数、负大小、溢出、资源级 `meta.error`、相同编号内容冲突 |
| 分页 | 根或目录后续页、新页带子目录、重复节点、令牌自循环和长循环、分页错误、总数不符、超限 |
| 预览 | 到期边界、设备及账号绑定、令牌续期、切换状态落盘异常、容量满、服务重启丢失预览 |
| 参数构造 | 只下发所选索引、连续区间压缩、全选仍为显式集合、所选大小、原资源总数、目标目录不变 |
| 幂等 | 排序与重复不改变同一集合；同编号修改集合被拒绝；两个选择集合使用不同指纹 |
| 保存与断线 | 发送前保存失败不创建；响应丢失不重发；保存任务编号失败保留已取得的远端结果 |
| 核对 | 选择一致、不一致、缺失、超大区间、多个候选、选择缺失候选不能忽略、原时间及分页边界 |
| 历史兼容 | 旧已知任务可复用、旧未知磁力不重发、过期预览仍可检查已提交记录、记录缺失不创建 |
| 网页服务 | 新接口同源保护、正文大小边界、错误映射、未知字段拒绝、检查接口不会调用创建 |

时间相关测试优先复用现有测试约定或注入可控时钟，不依赖长时间等待。

### 13.2 页面脚本测试

扩展 `pkg/remoteweb/app_test.cjs` 和必要的模拟能力：

- 点击解析后没有创建请求，取消或零选择也没有创建请求。
- 目录三态、全选、取消全选、仅视频、排序后索引不变。
- 批量部分解析失败，成功项的选择不被覆盖，提交数量说明准确。
- 关闭重开、编辑链接、切换账号或设备时，迟到的成功、错误与收尾不影响新窗口。
- 创建按钮连点只发送一次；提交中的选择被冻结。
- 刷新后未知项只调用检查接口；旧存储迁移不产生创建请求。
- 内容版本变化时不自动恢复旧选择，内容相同时可恢复。
- 存储容量满、存储不可用、预览过期都不会绕过原请求编号保护。

当前节点模拟不是实际浏览器，还需手动或浏览器自动化检查布局、复选框、键盘操作、窄屏及滚动。按运行环境已有浏览器规则执行，本机专用服务地址和脚本不提交进仓库。

### 13.3 真实设备联调

使用可公开分发且文件内容已知的多文件种子，以及专用测试下载目录。先确认解析链路，再创建测试任务，不要拿未知大体积资源验证。

1. 记录设备套件版本，确认获取的叶子索引及目录与种子一致。
2. 只解析并关闭窗口，确认任务列表没有新增任务，下载目录没有开始产生内容。
3. 选择少数不连续索引，核对创建参数、设备任务、最终完整文件和总大小。
4. 覆盖嵌套目录、单文件磁力、迅雷链接包装及一次明确的解析失败。
5. 检查任务列表或详情是否稳定返回原选择集合，决定核对实现能采用哪些证据。
6. 用受控故障模拟响应丢失，再通过原请求编号核对，确认不会发送第二次创建请求。

BT 分片可能跨文件边界，下载引擎也可能建立临时文件或预分配未选文件。因此不能把“出现任何额外路径”或“网络字节略多于所选大小”直接判为失败。需要区分占位文件、边界分片和实际完整下载未选内容，记录当前迅雷引擎行为。验收重点是任务选择正确、未选内容不被作为完整文件下载，并向用户如实说明实际边界。

如果当前环境没有可用账号或设备，先完成模拟测试及实现，并明确列出尚未实机验证的事项，不把模拟响应描述成端到端通过。

### 17.3 资源计数误判修复

用户反馈正常链接被提示「资源文件列表不完整或结构异常」后，复核发现初版将所有节点的 `file_count` 都与递归叶子数量比较。这超出了官方脚本能够证明的字段语义；官方创建参数仅使用顶层资源的 `file_count`。现改为只核对根资源明确提供的总数，叶子及子目录的计数仍检查整数合法性，不据其零值或其他摘要数量拒绝完整文件树。

新增回归用例模拟非根计数为数字或字符串零值、其他合法摘要值：旧实现拒绝完整树，修复后解析及显式索引创建通过。根总数不符、缺失索引、分页循环等保护继续保留。结构错误现在附加稳定中文原因，便于定位实际响应差异，不输出私人链接、资源名称或上游完整对象。这些用例是模拟数据；用户报告的具体链接仍需实际响应核对。

本次修复通过全量 Go 测试、远程模块竞态检查、40 项页面脚本测试，以及 linux/amd64、linux/arm64 静态检查和编译。页面布局与创建协议未改变，未重复浏览器布局验证或声称真实链接已验证通过。

### 17.4 父级关系误判修复

后续反馈将错误定位为「目录与父级关系不一致」。初版在合并节点时要求上游 `parent_id` 与本地直接父节点完全相等，包括要求根节点父标识为空；这混淆了上游列表标识与本地文件树层级。官方模型按 `dir.resources` 遍历并将目录后续页合并到该目录，对未出现在资源映射中的外部父标识不会直接判为解析失败。

本地父级现按返回树和分页归属建立，根节点父级归一化为空；外部父标识及同一祖先链中的摘要标识不阻止预览。所有分页完整加载后再验证上游引用，树内跨目录父级、自引用和根节点指向后代仍拒绝。临时外部标识不进入内容版本，真实文件索引、所选大小及设备下载目录保持原校验。

新增回归用例覆盖根节点非空父标识、嵌套节点外部标识、树内祖先摘要、目录分页外部标识、仅在后续页出现的冲突节点及自引用；旧实现复现相同错误，修复后完整树及显式选择创建通过，真正的树内冲突继续拒绝。这些用例仍为模拟数据，具体链接的上游响应尚未获取。
